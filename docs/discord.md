# 明日作戰表 → Discord（前一晚執行）

```bash
export Finlab_API_token=你的token
export DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...

python3 scripts/discord_daily.py                     # 送出
python3 scripts/discord_daily.py --dry-run           # 只印出
python3 scripts/discord_daily.py --only-if-action    # 沒有可能觸發的點位就不吵
python3 scripts/discord_daily.py --dry-run --as-of 2026-08-07   # 回放
```

## 為什麼改成前一晚跑

訊號以**加權指數 13:30 收盤**判定、成交在**當日台指期 13:45 收盤**，中間只有
15 分鐘。收盤後才算、才通知、才下單，時間根本不夠，雲端排程的延遲也不可控。

但所有觸發點位**前一晚就能全部算出來**：

| 點位 | 由什麼決定 | 明天會變嗎 |
|---|---|---|
| 停損線 | 訊號的 P 與 T | **不會** |
| 失效線 | 谷底 T | **不會** |
| 進場觸發價 | P、T 與補回門檻 | **不會**（除非破底） |
| 進場槓桿 | 風險預算 ÷ 停損距離 | 隨進場價變，已附換算 |
| 開始追蹤價 | 前高 ×（1 − 回檔門檻） | **不會** |
| MA200 交叉價 | 前 199 根收盤和 ÷ 199 | **不會** |
| 移動停利線 | 波段最高收盤 × 0.92 | 只會**往上**移（對你有利） |

所以流程變成：

```
今晚 21:00  收到作戰表，記下三個數字
明天 13:30  加權指數收盤，比對
明天 13:45  前下單（或什麼都不做）
```

**明天不必再跑任何程式，也不必等通知。**

## 訊息長什麼樣

```

依據 2026-08-07 收盤 44,225.91　→　下一個交易日的作法

🟢 收盤 ≥ 44,618（+0.89%）　→　13:45 前買進，槓桿約 3.57x（每 625,005 元 1 口小台）
   進場後停損線 43,618、失效線 39,933，兩條都已固定，不隨進場價變動。
   收得越高、離停損越遠，槓桿會自動降低：
   收 44,618 → 3.57x；收 45,064 → 2.49x；收 45,511 → 1.92x。
🔻 收盤 < 39,933（-9.71%）　→　破底，谷底與計時全部重來，觸發價跟著下移

── ② 今天發生了什麼 ──   今天是否剛觸發／剛出場，以及目前分區
── ③ 部位現況 ──         進場日、槓桿、損益、MFE/MAE、距各條線多遠
── ④ 劇本追蹤 ──         追到哪一段回檔、視窗剩幾天

```

持有部位時的版本：

```
── ① 明天 13:30 比對收盤價 ──
🔴 收盤 < 43,618（-3.55%）　→　13:45 前全數平倉
⬆️ 收盤 > 47,742（+5.57%）　→　創前高，啟動移動停利
🟡 以上都沒發生　→　續抱，不動作
```

## 明天要注意的點位（怎麼讀）

### 空手・追蹤中

1. **進場觸發價**（🟢）—— 收盤**等於或高於**它就進場。
   注意是**收盤價**，盤中穿越不算。
2. **谷底/失效線**（🔻）—— 收盤跌破它，這一段回檔的谷底就更新成新的低點，
   修復計時歸零，**進場觸發價會跟著往下移**。當晚的作戰表會重算。
3. **視窗剩幾天** —— 從谷底算起 30 個交易日內沒補回 60% 就作廢。
   剩 ≤3 天時 `--only-if-action` 會強制推播。

### 持有中

1. **停損線**（🔴）—— 固定不動。收盤跌破就當天 13:45 前平倉，不留倉、不攤平。
2. **移動停利線**（🔴，創高後才有）—— 只會往上移。若明天創新高 H，
   下一版的線就是 H × 0.92；不創高就維持原值。
3. **前高**（⬆️）—— 收盤站上它才啟動移動停利，在那之前只有停損線一條。

### 兩個都要看的

**MA200 交叉價** —— 核心部位（`docs/coverage.md` 驗收後保留的唯一改良）
只在策略空手時持有 0.5x。有策略部位時這欄顯示「不啟用」。

## 做法：明天 13:30 的三十秒流程

1. 看加權指數收盤價（13:30 定案）。
2. 對照作戰表的 🟢 / 🔴 一行 —— 有觸發就執行，沒觸發就關掉。
3. 若要下單，在 **13:45 台指期收盤前**送出，數量照作戰表的「每 X 元 1 口小台」換算。
4. 收盤後不用做任何事，當晚的作戰表會自動更新。

**下單原則**

- 一律**市價或收盤價附近**成交，不掛限價等更好的價格 —— 回測假設就是收盤價成交，
  等不到就整筆錯過，而錯過的常常是最大那幾筆（前 5 筆佔總報酬 90%）。
- 口數**無條件捨去**。湊不到一口就是不做，不要為了參與而超額下注。
- 進場後**不調整口數**直到出場（回測就是這樣算的）。加碼會讓實際風險超出預算。

## ⚠️ 需要注意的四件事

**1. 停損比你以為的更容易被穿透。**
`docs/tx_evaluation.md` 的體檢顯示，10 筆虧損中有 **6 筆**的實際虧損超出 8% 的
風險預算，實際跌幅是假設停損距離的 **1.3 ~ 2.1 倍**（2004 那筆假設賠 2%、實際賠 17.8%）。
原因是訊號在收盤才判定、期貨還會隔夜跳空。**停損線不是保證，是參考。**
槓桿越高（停損越近）這個誤差被放得越大。

**2. 錯過訊號日就不要硬追。**
若某天沒看到通知、隔天才發現訊號已觸發，②「今天發生了什麼」會提示你。
但隔天補進的進場價與停損距離都跟回測不同，風險更高。
**寧可整筆放棄，等下一次訊號。**

**3. 作戰表只涵蓋台指期。**
UPRO / TQQQ 的部位不在這份通知裡（美股指數與 ETF 同時收盤，沒有 15 分鐘的空間，
本來就是隔日成交）。

**4. 資料延遲。**
若 FinLab 當天尚未更新，腳本會印出警告並沿用最後一根 K ——
那份作戰表的點位仍然正確（它們本來就由更早的資料決定），
但「今天發生了什麼」會是舊的。標題的日期就是依據哪一天的收盤，比對一下就知道。

## GitHub Actions 設定

Settings → Secrets and variables → Actions 建立：

| Secret | 內容 |
|---|---|
| `FINLAB_API_TOKEN` | FinLab 的 API token |
| `DISCORD_WEBHOOK_URL` | Discord 頻道的 webhook URL |

Discord webhook：頻道設定 → 整合 → Webhook → 新增 → 複製網址。

排程是 `0 13 * * 0-4` UTC＝**台北時間週日至週四 21:00**，
產出的是隔一個交易日的作戰表（週日晚上那次涵蓋週一）。
排程延遲在這個設計下無所謂。

本機 cron（台北時區的機器）：

```cron
0 21 * * 0-4  cd /path/to/joe_TWbackdraw && \
  Finlab_API_token=xxx DISCORD_WEBHOOK_URL=yyy \
  .venv/bin/python scripts/discord_daily.py >> /tmp/tw-daily.log 2>&1
```

## 驗證

`--as-of` 依據某一天的收盤回放，可以檢查作戰表有沒有預告到實際發生的事：

```bash
python3 scripts/discord_daily.py --dry-run --as-of 2026-08-07
#   → 🟢 收盤 ≥ 44,618 買進，槓桿約 3.57x
#   實際：2026-08-10 收 44,929 觸發，槓桿 2.74x（落在附的換算階梯上）

python3 scripts/discord_daily.py --dry-run --as-of 2026-07-16
#   → 應預告移動停利線；實際 2026-07-17 跌破而出場

python3 scripts/discord_daily.py --dry-run --as-of 2021-08-18
#   → 應預告停損線 16,393；實際 2021-08-19 收 16,375 跌破而出場
```
